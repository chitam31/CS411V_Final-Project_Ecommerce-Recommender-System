# !Abstract

This report describes the design, implementation and evaluation of **bd03_khuyen_nghi**, a product recommender system for a simulated e-commerce marketplace, built as the final project (Topic 3) of the CS411 Big Data course. The system serves three recommendation blocks: a personalised "For you" list on the home page, "Related products" on the product page, and a "Trending now" block that must reflect user activity within 90 seconds. It answers three business challenges posed by the assignment: implicit feedback (only views, add-to-cart and purchase events, no ratings), cold start (brand-new users, users with few interactions and new items), and popularity bias.

The platform runs on six laboratory machines connected by a ZeroTier overlay network. All services run in Docker containers: HDFS 3.5 (one NameNode, five DataNodes, replication factor 2), a Spark 3.5.3 standalone cluster (five workers, 34 cores, 13 GB of executor memory), Kafka 3.7.2 in KRaft mode, Delta Lake 3.2, Apache Airflow 3.3.1 and a FastAPI web application. Events from the RetailRocket dataset (2.76 million events, 1.4 million visitors, 4.5 months) are replayed into Kafka at a compressed rate of one day per 30 seconds, with 5 % synthetic brand-new users. Three Structured Streaming jobs ingest events into a bronze layer, compute a 15-minute sliding-window trending score with a 2-minute watermark, and record impressions of the web application. A nightly batch pipeline cleans the data (deduplication, bot filtering, event weights), builds a time-decayed interaction matrix with a strict temporal split, tunes implicit-feedback ALS over a 27-combination grid, evaluates it against two mandatory baselines, and publishes blended recommendation lists with Delta MERGE. The lakehouse uses the Delta features required by the assignment: MERGE, time travel, schema evolution, Change Data Feed, OPTIMIZE/Z-ORDER and date partitioning.

On the real dataset the best ALS model (rank 50, regParam 1.0, alpha 40) reaches NDCG@10 = 0.0680, a 1,237 % uplift over the best-seller baseline (0.0051) and 43 % over the category baseline (0.0475). Its catalogue coverage is only 3.44 %, below the 10 % target; an analysis of the popularity distribution shows that 99.2 % of the recommended slots fall into the 10 % most popular items. A novelty re-ranking over 200 candidates (β = 1.0), now used in production, raises NDCG@10 to 0.0865 and coverage to 6.47 % at the same time. After a schema evolution added price and star rating to the silver table, the nightly pipeline itself deployed model version 2, which keeps candidates within the user's price range and adds 2.1 % to NDCG@10. A simulated A/B test with 350,160 impressions shows that blending 30 % trending items into the personalised list lowers the click-through rate from 2.094 % to 1.978 % (p = 0.015; p = 0.029 with a user-level bootstrap). Z-ordering the recommendation table by user reduces the files read per user lookup from 67 to 1.07 and the median latency 8.4 times compared with compaction alone. On the live system, a click on the web page reaches the trending block in 51 seconds (target 90 s). Re-running the selected experiment on Delta version 0 of the feature table through an Airflow DAG reproduced the recorded metrics with a deviation of 0.000000, even after the source tables had evolved. Finally, choosing the hyper-parameters and β on a separate validation period selects exactly the deployed configuration, which on held-out days keeps a 40 % (ALS) and 80 % (re-ranked) advantage over the category baseline, and an offline experiment that gives the last three slots of the list to co-occurrence candidates raises coverage to 14.5 %, above the target, while NDCG@10 also rises to 0.0892.

The report covers the theoretical background, the system architecture, configuration management, the implementation of every component, the experimental results against the eight acceptance criteria of the assignment, and the operational problems met on a resource-constrained shared laboratory cluster together with the lessons learned.

**Keywords:** recommender systems, implicit feedback, alternating least squares, Apache Spark, Structured Streaming, Kafka, Delta Lake, lakehouse, Airflow, A/B testing, reproducibility.
