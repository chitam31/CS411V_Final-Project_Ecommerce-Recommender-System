Data and architecture

Six layers, one direction of flow

Sources

Replay producer, web application events

Ingestion

Kafka 3.7 (KRaft): retailrocket-events, hien-thi

Storage

HDFS 3.5 + Delta Lake 3.2: bronze, silver, features, gold

Processing

Spark 3.5.3: three streaming jobs, a dozen batch jobs

Orchestration

Airflow 3.3.1: five DAGs

Serving

FastAPI web app with a local Spark session, five screens

Everything runs in Docker containers started from one directory file, cau_hinh/cum.env.

The architecture has six layers and data flows in one direction. Events come from the replay producer and from the web application, enter Kafka, are stored in the lakehouse, processed by Spark streaming and batch jobs, orchestrated by Airflow, and served by the web application. Everything is containerised, and every script reads the same directory file, so moving a role to another machine is a one-line change — we actually did that for the web host.
