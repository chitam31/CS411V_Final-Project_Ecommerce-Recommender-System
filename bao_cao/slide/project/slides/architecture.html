Figure 1. Architecture by role: each column is a component, each row is a flow; Airflow only orchestrates the Spark jobs

Read the figure in two directions. Down the columns is what each component does: Kafka only ingests and buffers events; Spark does all computation; HDFS with Delta Lake only stores tables and their versions; the web serves recommendations and sends feedback; Airflow, in the bottom band, only schedules and calls spark-submit and processes no data itself. Across the rows are the three flows. Flow one is continuous: the producer and the web push events into Kafka, and three Structured Streaming jobs write bronze, the trending table and the impression log. Flow two is the nightly batch at 2 a.m.: Spark jobs read bronze and write silver, features and then gold. Flow three is serving: the web reads gold, and every click, add-to-cart, purchase and impression goes back to Kafka, closing the loop.
